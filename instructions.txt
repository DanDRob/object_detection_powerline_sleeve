<goal>
- I have been given a project by a Canadian, specifically Ontario, electricity provider, HydroOne. The project goal/aim is to find the total number of powerline sleeves found throughout the province. 
</goal>
<current_implementation_steps>
- The process and steps I have decided upon is utilzing object detection with YOLOv12l via the ultralytics python library. I will use a multi-step process:
    - Collecting images locally via google streetview api.
        - The routes/ roads in which to collect the images from are found in a csv file called routes.csv.
            - Each route has the following attributes: route_id, start_location,end_location, save_images, draw_detections, generate_map
        - The parameters to be used for the streetview api are found in the config.yaml file in the root directory.
            - The detailed configuration is found under api, sampling, camera, powerline & system. 
                - api contains features such as the api key, number of retries allowed, and the length and width (dimensions) of the images.
                - sampling contains the desired distance between each point along the route.
                - camera contains the features for images to be taken at each specific point. For example it contains the pitch, fov, angles and altitude values. 
                - powerline contains the estimated distance between the centreline of the road and the powerlines and if the program should capture both sides of the road or only the left or right sides.

    - Labeling the various routes and the subsequent images captured using labelme a model to detect powerlines as the sleeves can only be found on powerlines.
        - Labelme produces a json file containing labels for each of the images thus a script to convert these labels to the required format for YOLO models such as labels being in a txt file, and normalization of the location of the each of the labels to between 0 and 1 was conducted. Additionally spliting these images into train and val sets or train, val and test sets was conducted. (85% train, and 15% val).
    - Various additional python scripts were created to also check and verify the dataset/sets
    - Utilizing lambdalabs gpu instance renting a a YOLOv12l model was trained on over labeled 2600 images with around 60% containing powerlines.
        - The parameters and configuration used to training the model is found in the config.yaml file under the comment/section: # Configuration for YOLOv12l Training
        - The model yield around 77% precision and recall scores which was satisfactory.
    - I then collected images along a new route which would act as an unseen dataset to check the models ability to perform on unseen data and using a confidence of 0.25 and manually checking all the 168 images, 1-2 images w/ powerlines were missed and 1-2 images w/o powerlines were detected to have.
    - Now that the powerline model is verified it will act as a filter for the detection of powerline sleeves. As we know sleeves can only be found on powerlines thus images without powerlines will be useless be wasted images to then pass to the trained sleeve model, causing noise which might lead to incorrect predictions to be made. The sleeves on the powerlines are very small and thin and thus this is one of tactics I have employeed to maximize the sleeve model performance.
</current_implementation_steps>

Therefore, instead of going along a route in only one direction and looking at both sides, I could just go from the start to end locations and then from the end to start location, in the opposite direction and on the other side of the road along a route. This would allow a narrower set of camera parameters to be used, thus enabling a reduction in the number of images captured while retaining important datapoints along the route for the ultimate goal of collecting powerline sleeves for labeling and then detecting them in the future for inference.
- Presently all routes are found within the routes.csv file. This has been used to be able to gather specific routes I deem as import for training as they have data I want. But when all the training is complete and the model is ready to conduct inference, this approach will be unsatisfactory and not feasbile. As the project needs to be able to find the sleeves for all of ontario, putting start to end locations to cover such a large area is impossible.
